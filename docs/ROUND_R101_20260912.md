## 3. 缺陷与处置（本轮核心产出）

### D1 快照门禁口径随解释器变化（已修）

- **复现（修复前）**：`python tools/gen_devplan_snapshot.py --check` → `snapshot STALE - run --update`（exit 1）；
  `& $py tools/gen_devplan_snapshot.py --check`（occ）→ `snapshot current`（exit 0）。
- **根因**：生成器用 `len(live_commands())` 填「内核不可用」格——它回答的是**跑它的解释器**；提交块由 OCC
  环境生成，于是两格都写 177。**同一个数在两个条件下相同，说明它测的不是那个条件。**
- **修复**：`live_counts()` 从 `M1_LIVE` / M2..M5 清单直接算两格；`tests/test_snapshot_tool.py` 用
  monkeypatch 把 `available()` 置 False 验证「不可用 live == |M1_LIVE|」与解释器无关。
- **验收**：两种解释器 `--check` 均 `exit 0`（本轮实测）；自动块改为 `**29 live（内核不可用）** / **177 live（内核可用）**`。

### D2 已实现、已 live、无 UI 入口（已修）

- **现象**：`con.perp` / `con.mid` 在 `M3_LIVE` 中且 `scdm_gui.py` 有真实处理器（`kind == "perp"`
  需要两条线段的校验、`"mid"` 需要线段 + 点），但目录里是**合并按钮** `con.par`「平行垂直 / Par/Perp」与
  `con.fix`「中点固定 / Mid/Fix」——**按钮承诺两件事，处理器只做一件**，另一条路径从 UI 不可达，
  且 `all_commands()` 不列它们，覆盖率台账因此漏算。
- **修复**：四条独立命令 + 两个新图标 + 新不变量 `test_every_live_id_has_a_command_entry`（live ⊆ 目录）。
- **验收**：ribbon 162→164、目录 176→178、快照同步；不变量在旧代码上必失败（`con.perp`/`con.mid` 不在目录）。

### D3 命令面数字多口径混用（已收口）

`DEV_PLAN.md` 自动块同步刷新（纪律 84）。
