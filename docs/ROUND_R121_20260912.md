## 3. 更正上轮的一条边界（纪律 86 的口径）

R120 的边界 2 写的是「只读只覆盖命名选择/组：导入组件上的配合仍可被删除（组件没有 imported 标记）」。
本轮查证：**本仓库的导入器（`scdm/import_sab.py`）不创建组件**，只产出实体 + 只读分组（`imported: True`），
组件全部是用户自己建的 —— 所以「导入组件的配合」这一类对象**不存在**，那条边界是无的放矢。
结论：配合不需要只读标记；导入结构的只读护栏（分组/命名选择）已覆盖实际存在的只读对象。
这条更正记在这里，避免下一轮再按错误前提排期。

## 4. 边界（转 R122）

1. **勾选仍在树上做**：预览文本本身不可勾（树多选就是勾选）；预览只是「将要做什么」的清单。
2. **锚点靠库层/脚本给**：GUI 的阵列选项页没有锚点输入（路径起点仍是 GUI 默认）。
3. **改指向目标只认草图**：不能指向参数表、不能跨文档；目标草图必须已有同序号尺寸行。
4. **`exclude` 按告警 id 匹配**：同名条目同 id 会一起跳过。
5. **A-4 尺寸驱动预览、A-5 拉前重解、A-7 三维模式选草图** 仍顺延；装配线仍在等 **B-1**。

## 5. 口径与纪律（R121 新增）

1. **挑选要有两个方向**：「只做这些」与「跳过这些」是两种自然表达，缺一个就等于逼用户反着数。
2. **目标从界面里点，不从脑子里数**：能选就不要让人填序号（序号会变，选中不会）。
3. **锚点显式化**：「几何的哪一点跟随路径」必须是参数，默认值只是默认，不是假设（默认 = 路径起点，
   几何不在那儿时会整体平移 —— 这正是要显式化的原因）。
4. **前提错了要更正**：边界若建立在「某类对象存在」的假设上，先查证再排期；查证不成立就写进文档，
   不要留一条没人能实现的待办。
