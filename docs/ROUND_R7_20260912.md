## P45 定位：三个独立缺陷

R6 结束时留有四处保真度尾巴（samplemodel2 部件 7/23 漂移、samplemodel3 11/111、
SampleModel1 96/109、SampleModel4 92/177）。本轮逐面取证后确认其中**三处是同一批
"几何来源不可信"问题**，与 R6 猜测的"UV 区间/半径解码错"并不完全一致：

### ① 柱面（`cone` 零半角）面被造成"整圈 2π 大圆柱"

旧代码用**边界椭圆圆心在轴上的投影**推轴向区间，再用**整模型 bbox 夹取**。官方流里
少量边携带的曲线属于**另一个曲面**（实测投影出现 ±100 m、+38 m 等值），于是造出
几十米外的柱面片；夹取到整模型 bbox 又会把 7 m 半径的大圆柱拉成整模型长，**反而更远**。

修复（`scdm/import_sab.py`）：

1. **轴向区间 = 面自身记录 bbox 在轴上的投影**。投影是线性泛函，极值必在 bbox 角点取到，
   所以这是**精确区间**（不是近似），且完全绕开不可信的曲线参数。
2. **周向区间 = 圆与"面 bbox 沿轴投影凸包"的交**（`_proj_hull` + `_circle_hull_arcs`）。
   半平面约束化成 `cos(u-φ) ≤ c/r`，逐个求交；跨越 0/2π 接缝的两段用 `_merge_seam` 合并
   （这是"一个孔被切成两个面"的直接原因），接缝处只差发丝级缝隙时吸附回整圈。
3. **兜底**：仅当解析窗口仍越出面 bbox（>0.5% 对角）时，才用**面 bbox 实体布尔裁剪** +
   `ShapeUpgrade_UnifySameDomain` 缝合。布尔从 622 次降到少数，samplemodel2 导入
   11.2 s -> 4.5 s。

### ② 直线边端点：曲线参数 vs 顶点表必须交叉校验

`edge_endpoints` 原来优先"边自己的 pstart/pend + 曲线原点方向"。实测**两个来源大面积冲突**：

| 样例 | 直线边 | 冲突 | 冲突中"曲线端点出 bbox" | "顶点出 bbox" |
|---|---|---|---|---|
| SampleModel1 | 219 | 37 | 1 | **0** |
| SampleModel4 | 14 | 4 | 2 | **0** |
| samplemodel2 | 3013 | 573 | 265 | **0** |
| samplemodel3 | 104 | 80 | 26 | **0** |
| samplemodel5 | 2964 | 4 | 0 | 0 |
| samplemodel6 | 40 | 0 | 0 | 0 |

凡是"两个来源有一个落在模型 bbox 外"的情况，**全部是曲线参数那一个**（294 : 0）。
顶点来自独立的 point 表，是可判定的真值。新规则：两来源差异超过线段尺度 1e-4 时以**顶点**为准。
单这一条就把 samplemodel3 从 11 面推到 **111/111 精确**，并让 samplemodel2 找回第 37 个部件
（20 m 长的 6 面长方体，之前因环多边形构造失败整个丢失）。

### ③ bbox 判据本身要分两层

`_shape_within` 原先用"实体顶点探索"（2344 次调用 2.1 s），改为 `Bnd_Box`（快 ~20 倍）；
同时**模型 bbox 只能当"离谱几何"的兜底**：它由 point 表得到，是模型真实范围的**下界**
（samplemodel6 面 z=0.3999 > 顶点 bbox 0.347）。所以面级判据用**面自身 bbox**（±0.5% 对角），
模型级判据放宽到 **±50% 对角**，只用来拦"几十米外"的错位片。

## P46 关键成果：官方解析曲面族

先把“重建失败”的面逐个分类（而不是猜），得到精确清单：

| 失败类别 | SampleModel4 | samplemodel2 | 处理 |
|---|---|---|---|
| cone 半角锥 | 5 | 38 | ✅ |
| torus 环面 | 13 | 32 | ✅ |
| 平面多环 / 退化环 | 30 | 74 | ✅ |
| spline（簇载荷缺失） | 52 | 2 | ⏳ 下一轮 |

### ① 锥面：token 10 不是角度，是 sin

官方 cone 记录尾部三连是 **sin(半角)、cos(半角)、基准半径**（圆柱写作 -0.0 / 1.0 / R）。
旧码把 token 10 当角度，于是**所有截锥都被当成圆柱**（samplemodel2 有 38 个）。
修正：semangle = atan2(sin, cos)。

还有个反转陷阱：**cos 为负表示轴是反存的**（samplemodel6 的圆柱就是 sin=-0.0, cos=-1.0）。
直接 atan2 得到 ±π，圆柱被翻成“180° 锥”，samplemodel6 立刻丢 6 个面。
处理：cos<0 时翻转轴并取 atan2(-sin, -cos)。

### ② 环面：两个半径夹在轴与 x 方向之间；只有记录 uv 窗口才是精确解

torus 记录是 origin, axis, major, minor, xdir——两个 double 插在两个 vec3 中间；
按“vec 位次”取 origin/normal/xdir 恰好仍然正确，半径取 _doubles() 的前两个。

环面片**无法只靠 bbox 恢复**：一个圆角环的 bbox 是一层薄板，曲面**穿过它两次**。
所以新增 _face_from_window：按记录 uv 窗口建面，再用**面自身 bbox 反查**该读法是否正确
（uv 四连的排列有 (u0,u1,v0,v1) / (u0,v0,u1,v1) / (v0,v1,u0,u1) 三种，再叠加各段符号翻转，
共 12 个候选，取 bbox 误差最小者；误差 >2% 退回布尔裁剪）。
本节的通用收获：**先用记录 bbox 判定解码口径，再建几何**。

### ③ 平面多环与“两边形薄片”

- 多环：_face_from_polygons 取 |面积| 最大者为外环，其余**反向**作为内环——
  不反向的话内环面积会**加到**面上（单测直接覆盖：带方孔的面 = 外环 − 内环）。
- 退化环：官方有一种面，环里只有 **2 条边**（一条直线 + 一段 7 m 半径圆弧，围出 0.0055 宽的薄片），
  环游走只能得到 2 个点；新增 _loop_polygon_sampled 按 coedge 顺序**采样曲线**重建边界多边形。

## P47：导入降级必须可见 + 兜底按部件

### ① 结构化导入报告（数据层）

导入器原则上“静默降级”（一个部件缝合失败不应阻止打开其余内容），但用户看到的只是
“几何少了”。现在 KernelDoc.import_report 给出可机读事实：

parts / failed_parts（带部件 doc id）/ unbuilt_faces / dropped_faces / mesh_bodies。
摘要行由 Qt 无关的 import_summary() 生成，例：

- “1/25 个部件未重建；2 个面未重建；4 个面被丢弃；未重建部件：0:23”
- 内核缺失时不再“打开成空文件”：Session.import_error 记下原因，摘要为“几何未导入（内核不可用…）”。

GUI：open_path 收尾调 _report_import，状态栏总是显示摘要；**只有丢失部件或几何构建失败才弹非模态对话框**（丢几个面
只留状态栏），且**窗口未显示时不弹**——offscreen 平台下 QMessageBox 会直接崩溃（本轮实测）。

### ② 网格兜底：从“整文件一次”到“按失败部件”

facets 流本来就是**按 body 分段**的（[bid, X, upd, Y, n_faces, Z] + 该段的 face 索引），
只是段首的 id 与 SAB body doc id 前缀不同（SAB “2:399” vs facets “0:399”）。
新增 _facets_nodes_of_model：先按全 id、再按 **数值后缀**对接，实测 samplemodel2 的 **54972/54972**
三角形全部归位到 25 个部件。于是 mesh_fallback='always' 只为**失败**部件建网格体
（命名“网格导入 <doc id>”），新增体数 ≤ 失败部件数；默认 'auto' 仍然只在“完全没建出任何实体”时兑底，
避免把 48 s 的全文件网格重新引入默认路径。

### ④ 官方 B 样条：SAT 对拍定死 `nubs` 布局（P46b）

官方样条簇的载荷不是自研写盘的 `nurbs`+`both`，而是一个 **`nubs`** 作用域。
用官方 `SabSatConverter` 把同一份 SAB 转成 SAT 文本后，**布局无需猜测**：

```
spline-surface $-1 -1 -1 $-1 forward { exactsur 0 full nubs 3 3 periodic open none none 33 4
	0 3 0.03125 1 ... 1 3            # u: 33 组 (knot, mult)
	-0.01 3 0 3 1 3 1.0101 3         # v: 4 组 (knot, mult)
	0.091080086808983662 0.0024999999999999953 0.027499999999999997   # 极点 XYZ（非有理）
```

由此得到可判定的字段表：`[deg_u][deg_v][4 个 flag][n_u_knots][n_v_knots]` + n_u、n_v 组 (knot, mult) +
**npoles_u × npoles_v 个 3 元组极点**；`npoles = Σmult - deg + 1`（开放方向端点重数已预减，需 +1）。
校验：Σmult = 38 / 12、deg = 3/3 ⇒ **36 × 10 = 360** 个极点 ⇒ 1080 个 double，与记录的 1121 个剩余 double
减去尾部 41 个（`0 0 0 32 <32 个 knot> 0 2 0 1 0` 的 exactsur 缓存）**完全吻合**。
极点存序有 u 快 / v 快两种可能，实现里**两种都构造**，再由“面 bbox 自校验”选对的那个（沿用 P46 的口径判定法）。

**战绩**：SampleModel4 的 71 个样条面里 19 个可直接重建（156 -> 161 面）。

**余下 52 个是 `ref` 型样条面**：簇头 `spline` 记录为空，唯一内层记录是 `ref`，其载荷是
`int 1` + 4 个 double（**面的 uv 窗口**），**没有曲面数据本身**。全模型统计：71 个 spline 实体中
19 个带 `exactsur`、52 个只有 `ref`，且这 52 个都被面引用；`exactsur` 的拥有者另有 26 个 pcurve、10 个 intcurve
（曲线级曲面）。也就是说 **这 52 个面的曲面数据不在本 part 的实体表里**，而官方 SabSatConverter 能 restore 出
全部 71 个 `spline-surface` ——说明 `ref` 指向的几何存在别处（另一段/延迟节），**下一轮的首要目标**：
用 SAT 里这 52 个 `spline-surface` 与 `ref` 记录的 uv 窗口配对，定位它们在 SAB 中的存储位置。

## P48：尺寸拖拽手柄 + stale 提示

### ① 模型层：拖拽是“只改偏移”的操作（可证）

`Dimension` 新增：

- `normal()`：该尺寸偏移方向（h→+v、v→+u、任意边→法向）；
- `handle_point()`：手柄位置（尺寸线中点，与 `text_at()` 同源）；
- `offset_for_point(p)`：把尺寸线移到 p 所需的偏移（投影）；
- `drag_to(p, minimum=None)` / `drag_by(du, dv, minimum=None)`：只写 `offset`；
  门槛是 opt-in 的（尺寸可以合法地放在区间两侧，负偏移必须允许）。

**验收判据用单测钉死**：拖动前后 `value_mm`、端点 `a/b` 与实体体积**逐位不变**；
`offset_for_point(handle_point())` 回到原偏移（手柄在线上的自洽性）。

### ② stale 尺寸不再是“自信的错数字”

`refresh_dimensions` 找不到关联边时，过去只返回 stale 计数、对象上不留痕。现在写 `Dimension.stale`，
SVG 里以**橙色 + 值后加 ?** 输出（`#c60` / `20.0?`），正常尺寸仍是红色 `#b00`。

### ③ 导出跟随拖拽：`svg_sheet`/`write_dxf` 接受实时尺寸对象

两个函数原来只接受 `dimensions=True/False`，内部**重新生成**尺寸——拖过的偏移根本导不出去。
现在 `dimensions` 可以是 True（自动生成）/ False（不画）/ **Dimension 列表**（调用方持有，
拖拽偏移与 stale 标志原样导出）。这条是“拖动只改 offset + 导出坐标随动”验收的关键。

### ④ GUI：`scdm/gui/sheet.py` 图纸预览画布 + `det.dim` 真实处理器

3D 视口没有图面，所以预览放在一个纯 QWidget 画布上：视图折线（灰）、尺寸线（红/橙）、
**每个尺寸一个黄色拖拽手柄**。画布提供与 Qt 事件解耦的可测接口：
`to_px/to_view`（米↔像素，y 翻转）、`handle_px(i)`、`pick(px,py,tol)`、`drag_handle(i,px,py)`，
鼠标事件只是这几步的封装（因此单测不需要合成事件）。

`det.dim` 原本只往状态栏写包围盒文本（DEV_PLAN 第 31 项列出的差距），现在打开
`SheetDialog`：选中实体 → 前视投影 → 尺寸列表 → 拖手柄 → 导出 SVG/DXF 带的就是拖动后的状态。

### 过程中被本轮改动打回并修好的回归（4 条自研往返测试）

`test_p02_coverage::test_self_read_cylinder_exact`、`test_g2::test_cylinder_scdoc_self_read_exact`、

纪律新增：**同一几何量存在两个独立来源时（曲线参数 / 顶点表），必须交叉校验，
冲突时以点表为准并留痕**；**导入类验收必须同时给数量与几何位置（bbox）**。
