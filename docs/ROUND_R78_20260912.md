## 1. 定位（P383）

samplemodel2 的 165 个不可裁剪柱面，逐边分解（684 条边可解码 / 287 条 `intcurve-nubs-unusable` / 14 条 `intcurve-no-nubs`）：
**287 条"有 nubs 却没有极点"** 是最大单因。逐条 dump 记录后看到：

| 现象 | 实测 |
|---|---|
| 记录结构 | `[form=3][int15=2][#knots=33]` + 33 组 (knot, mult) + **199 个 double** |
| 199 = ? | 199 ＝ 66×3 ＋ **1**：末尾多一个 double，值 **1e-05**（拟合容差） |
| 极点取值 | 从第 69 个 token 起是干净的坐标三元组；`start=70` 则错位 |
| 重数 | 首尾各为 3，其余 2；`sum(mults)=68`、66 个极点 ⇒ **degree = 3**（ACIS 关系式自洽） |

## 2. 两个缺陷与修法

1. **尾部容差 double**（`scdoc_parser/topology.py`）：解析器只认 `rest % 3 == 0`（和 2D 的 `rest % 2 == 0`），
   `199 % 3 == 1` 时整个记录被判成"无极点"。修：`rest % 3 == 1` 时把**前 rest−1 个** double 当极点（尾部那个丢掉）。
2. **端点重数预减 1**（`scdm/import_sab.py` 的 intcurve 分支）：ACIS 把首尾重数存成 3（OCCT 要 4）。
   把原始重数交给 `Geom_BSplineCurve` 会抛 `Poles and degree mismatch`，而这个异常被函数末尾的 `except` 吞掉——
   于是"极点已解出"的 287 条边依旧报"nubs 不可用"。修：`[m0+1] + m[1:-1] + [m-1+1]`（曲面路径 `both` 早就是这么做的）。
   顺带把裁剪区间从"整条曲线"改成"记录范围与曲线范围求交"（求交为空才退回整条）。

教训：**一个 except 吞掉两种完全不同的失败**（数据缺失 vs 构造参数错），定位时会被指向错误的方向——
本轮先修了数据缺失（尾部 double），症状"没变"，才逼出第二个原因。
