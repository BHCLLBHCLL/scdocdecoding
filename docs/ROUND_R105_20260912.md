# R105 轮次交付记录（2026-09-12）——草图 / 三维模式边界

> **触发**：用户反馈「草图和三维操作之间没有边界，不像 SpaceClaim 一样，无法丝滑切换」。
> 本轮先做**行为诊断**（改动前实测），再定义并实现边界契约：模式状态单一来源、草图专属页签与状态提示、
> 三维命令**自动越界后继续执行**、草图→实体一步完成并回到三维、活动草图明确、悬空平面拒绝。

## 1. 诊断（改动前实测）

| 现状 | 证据（改动前） |
| --- | --- |
| 模式状态隐式且分散 | `self.tools.mode == "mode.sketch"` + `ses.show_grid` + `scene.preserve_camera` + `self._sketch_state`；没有单一来源，也没有任何 UI 显示当前模式 |
| 没有草图专属界面 | SpaceClaim 有 `EditSketchRibbonTab`（官方 journal 扫描，见对标文档 §2），我们只有设计页里的「草图」组；页签不随模式变化 |
| 退出入口少 | 只有 Esc（且必须先取消绘制工具，第二次 Esc 才退出）或设计页的 `mode.3d` 按钮；没有「完成草图」 |
| **没有边界** | 草图模式下 `asm.*` / `create.*` / `tool.combine` / `sheet.*` 等三维命令照常可点、照常执行；执行完仍留在草图模式（网格、锁定相机、活动草图都在），也没有任何提示 |
| 草图→实体不完整 | `tool.pull` 未拾取到面时拉伸 **`kdoc.sketches[-1]`**（固定 10mm、无预览、不能选草图），成功后**不退出**草图模式 |
| 草图与三维的视觉联系 | 结构树里有草图节点，但双击无效；状态栏没有模式标识 |

## 2. 边界契约（本轮定义，全部有测试）

| 规则 | 行为 |
| --- | --- |
| **R1 进入** | `mode.sketch` 或任意草图工具（自动进入）；平面来自选择的基准面/平面面，缺省 XY；页签切到「草图模式」、状态栏出现模式 chip「草图模式 · XY」、网格开、相机锁定 |
| **R2 退出** | `sketch.finish` / `mode.3d` / Esc；**只有一个地方**跨边界（`_exit_sketch`）：清绘制工具、清会话、关网格、解锁相机、复位页签与 chip、状态栏说明；草图保留在树里可再进 |
| **R3 三维命令自动越界** | 草图模式下点三维命令：**先退出草图模式，再执行该命令**（一次点击完成，状态栏写明「已退出草图模式 → 命令」）——这就是"丝滑切换"的机制；视图/显示/测量/编辑等中性命令不越界 |
| **R4 草图→实体一步** | `sketch.pull`（或 `tool.pull` 未拾取到面）按 Pull 选项距离拉伸**活动草图**，成功后自动回三维 |
| **R5 活动草图明确** | `SketchSession` 记录活动草图；结构树双击草图节点可重新进入该草图；无会话且草图数 > 1 时**拒绝猜测**并提示去树里选 |
| **R6 悬空平面检测** | 依附面的草图在面被移动/删除后判为 `stale` 并拒绝拉伸（几何判据：同法向 + 同平面，与面序号无关）；面内平移不算失效 |

## 4. 关键实测

| 项 | 实测 |
| --- | --- |
| 策略表 | 14 个草图/中性命令 → `run`；10 个三维命令 → `exit_then_run`（理由含命令 id） |
| 悬空平面 | 面内平移 50mm → **仍有效**（几何判据，与面序号无关）；沿法向平移 50mm → 「平面已改变」；删除实体 → 「实体已不存在」 |
| 草图→实体（库层） | 矩形 10×8mm × 5mm → V = **4e-07**（闭式，rel 1e-9）；圆 ⌀4 × 10mm → **1.2546e-07** vs 闭式 1.2566e-07（多边形近似，rel 2e-3） |
| GUI 一键切换 | `mode.sketch` → `_mode()==sketch`、网格开、页签 `sketchmode`、chip「草图模式 · XY」；`view.fit` 不越界；`asm.mate`（无选择）→ **自动退出**（网格关、会话清空、页签回 `design`、chip 隐藏）并继续执行；`sketch.finish` 退出 |
| GUI 草图→实体 | `sketch.pull` 拉伸活动矩形 → 新增实体 V = **4e-07**（GUI 默认 5mm 选项）且 `_mode()==solid` |
| 命令面口径 | ribbon 命令 **166（去重，按钮 190 个）** / 目录全集 **180**；页签 19 ribbon + 1 backstage |

## 5. 边界（转 R106 候选）

1. **草图不是特征**：拉伸出的实体不记录"来自哪个草图"，改草图不会重建实体——下一步应把 sketch 作为一个 feature 进特征栈（与 R102 的参数编辑闭环合流）。
2. **圆/样条拉伸是多边形近似**（0.16% 量级）：需要真正的圆/样条截面拉伸面。
3. **模式不进撤销栈**：自动越界不计入 undo（模式切换是视图状态，重做时可能需要重进草图）。
4. **活动草图不持久化**：重开工程后要从结构树双击重进（`_sketch_session` 是内存态）。
5. **草图页签是 Design 页的重复按钮**（同一 id，去重后命令数不变）：若将来要"仅草图模式可见"的专属命令（阵列草图、镜像草图、草图文字），再单列 id。

## 7. 验收对照

| 用户反馈 | 结果 |
| --- | --- |
| 「没有边界」 | ✅ 专属页签（仅草图模式可见）+ 状态栏 chip + 策略表把草图/三维分成两类，视图/测量等为中性 |
| 「无法丝滑切换」 | ✅ 一键进（工具或命令）、一键出（完成草图/Esc/mode.3d）、**三维命令自动越界后继续执行**、草图→实体一步回到三维 |
| 「像 SpaceClaim 一样」 | ✅ 对齐官方 `EditSketchRibbonTab` 的形态（模式页签 + Pull 出体后回三维），并按我们的架构拆成"库层策略 + GUI 薄壳" |
